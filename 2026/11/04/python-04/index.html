📖 面向对象

🎬 对应课程:Python基础 第7章(类、三大特性、绑定方法、反射、元类)

1. 类与对象(类属性 vs 实例属性)

🎬 对应视频:P352~P357

类是模板**,对象是实例;__init__ 在实例化时自动执行;类属性所有实例共享,实例属性每个对象独有一份。**

  • 定义:class 类名:(大驼峰命名);实例化 p = 类名(参数) 自动触发 __init__
  • 实例方法的第一个参数 self 就是当前实例,实例属性靠 self.x = ... 绑定在对象上
  • 类属性写在类里方法外,所有实例共享;实例属性只属于一个对象
  • 取值先找实例属性,找不到再找类属性;实例.属性 = 值 是给实例新增属性,不会改类属性
  • 对象属性可以动态增删:p.age = 18、del p.age

类属性 vs 实例属性

2. 三大特性:封装 / 继承 / 多态

🎬 对应视频:P370~P371、P380

*封装隐藏细节、继承复用扩展(用 super 复用父类初始化)、多态*同一调用不同表现;Python 是鸭子类型,不强制继承统一父类。

  • 封装的弱私有:单下划线 _x 约定不外部使用;双下划线 __x 触发名称改写成 _类名__x
  • 继承:class Son(Father),子类找不到的属性方法去父类找;同名方法直接重写覆盖
  • super().__init__(...) 在子类里复用父类的初始化,避免重复代码
  • 多继承按 MRO(C3 线性化)从左到右查找,类名.__mro__ 可查看顺序
  • 多态/鸭子类型:不关心对象是什么类型,只要有那个方法就能调用

3. 组合与依赖

🎬 对应视频:P362~P363、P379

继承是“是”的关系(狗是动物),组合是“有”的关系(狗有尾巴)——把一个类的对象当属性,比继承更灵活,能用组合就少用继承。

  • 组合:在 __init__ 里把另一个类的对象赋给属性,如 self.tail = Tail()
  • 依赖:某个方法临时用到另一个类的对象(作为参数传进来),用完即走,关系最松
  • 继承层级过深难维护,组合可以随时拆装,课程建议:能用组合就不用继承
  • 经典例子:学生有课程、老师有课程 → Course 类被 Student/Teacher 组合复用

4. 绑定方法与 classmethod / staticmethod

🎬 对应视频:P381~P382

普通方法绑定给对象**(第一个参数 self);@classmethod 绑定给类(第一个参数 cls);@staticmethod 谁都不绑定,就是放在类里的普通函数。**

  • 对象绑定方法:通过对象调用时,解释器自动把对象传给 self
  • 类方法:通过类或对象调用都自动把类传给 cls,可以访问/修改类属性
  • 类方法常用来替代构造方法(工厂写法),如 Date.from_string("2020-03-01")
  • 静态方法没有自动传入的 self/cls,适合与类相关但不需要对象和类状态的工具函数
  • 普通函数写进类里就是对象绑定方法,加装饰器才能变成类方法/静态方法

5. property 装饰器与常用特殊方法

🎬 对应视频:P368~P369

@property 把方法伪装成属性访问,配 setter 做受控读写;__str__ 控制 print 显示,__call__ 让对象能像函数一样加括号调用。

  • @property 让 obj.score(不带括号)像属性一样取值;@score.setter 拦截 obj.score = 5 做校验
  • 好处:调用方写法不变,内部随时加校验逻辑
  • __str__:print(对象) 时调用,必须 return 字符串;没有 str 时退而调用 repr
  • __repr__:交互式直接敲对象名、放在容器里打印时显示;调试常用
  • __call__ 让 对象() 可执行;__eq__ 定义 == 行为;__len__/__getitem__ 支持 len() 和下标

6. 反射、isinstance 与元类简介

🎬 对应视频:P383、P406~P407、P410

反射四件套 getattr / setattr / hasattr / delattr 用字符串操作对象属性;isinstance 判实例、issubclass 判子类;type 既是查看类型的函数,也是所有类的元类。

  • getattr(obj, "name", 默认值) 取属性、hasattr 判存在、setattr 新增/修改、delattr 删除
  • 典型用途:根据用户输入的字符串动态调用方法(框架路由的思路)
  • isinstance(obj, 类) 判断对象是否是该类(或其子类)的实例;issubclass(A, B) 判断类的继承关系
  • type(对象) 查看类型;type("A", (object,), {}) 三参数形式可以动态创建类
  • 元类 metaclass:class 语句创建类的过程实际由 type 完成,自定义元类可拦截类的创建(了解即可)

7. 隐藏属性(__x 与名称变形)

🎬 对应视频:P364~P365

属性名以双下划线开头(__x)即被隐藏**:类外取不到,解释器偷偷把它改名为 _类名__x —— 这是”变形”不是加密,目的是逼外部走接口。**

  • __money 在类体内定义后,类外 obj.__money 报 AttributeError,但 obj._Person__money 仍能访问 —— 说明只是名称变形,并非真正私有
  • 变形只发生在类体内定义的名字:类外部自己赋值的 obj.__x 不会变形,只是普通属性
  • 为什么要隐藏:余额、密码这类数据不能让使用者随意改;隐藏后只暴露有限的接口方法,在方法内部做校验(“存钱必须为正数”),控制权收回类手里
  • 函数同样可以隐藏:def __run(self),思想一致 —— 对外接口越少越稳定
  • 单下划线 _x 只是约定“别在外部用”,Python 不做任何拦截;双下划线才触发变形

隐藏属性与接口

8. Mixins 多继承机制

🎬 对应视频:P376

Mixin 是多继承的”守规矩”用法:主功能放主父类,附加功能拆成一个个 Mixin 类(命名 Mixin/able 结尾),按需自由组合。

  • 多继承的问题:父类一多,结构容易乱;Mixins 约定让多继承有秩序 —— 继承列表里只有一个主父类,其余都是功能插件
  • 规范:Mixin 类功能单一、不单独实例化,类名以 Mixin / Flyable / Runnable 等结尾,一眼看出它是”功能包”而不是”物种”
  • 经典示例:主干 Animal 提供 __init__、eat;FlyMixin 提供 fly;鸭子类 class Duck(Animal, FlyMixin) —— 鸭子是动物(主),会飞(功能)
  • 查找顺序按 MRO 从左到右:属性先 Animal 再 Mixin,主父类写在前;Mixin 里只放增量功能,别和主父类重名互相干扰
  • 标准库大量使用:socketserver 的 ThreadingMixIn 给服务器加多线程能力,django 的视图 Mixin 也是同一思路

Mixins 组合功能

9. 属性查找顺序(对象 → 类 → 父类)

🎬 对应视频:P372、P374、P377

obj.x 的查找路线:对象自身 → 类 → 按 MRO 依次找父类 → object,全链找不到才抛 AttributeError;方法同样走这条链。

  • 第一步查对象自己的名称空间(init 里 self.x = … 创建的实例属性);没有才去类里找
  • 类里也没有 → 沿 MRO(类.mro 可查看)从左到右搜父类,终点是 object;全程未命中才报错
  • 方法查找同理:子类重写后,对象调用的永远是离它最近的版本 —— 这就是”重写生效”的原理
  • 想跨过重写版本直接用父类功能:父类名.方法(self) 或 super().方法()(按 MRO 找下一个,推荐)
  • 遮蔽现象:obj.x = 新值 是给对象新增实例属性,不改类属性;但此后查找先命中对象级,类属性被”挡住”

属性查找顺序

10. new 与单例模式

🎬 对应视频:P413

类名() 先执行 new(cls) 创建并返回对象,再把它交给 init 初始化;重写 new 让类”永远只产出一个对象”,就是单例模式。

  • 分工:new 负责”造对象”(第一个参数 cls,类级别);init 负责”初始化对象”(第一个参数 self);new 必须返回实例,init 才会被调用
  • 默认流程看不到:object.new(cls) 造出实例 → init 给它挂属性 → 返回给调用方
  • 单例写法:类属性 __instance = None;new 里第一次创建并保存,之后每次都返回同一个实例 —— a = Singleton();b = Singleton();a is b → True
  • 用途:全局只需一份的对象 —— 配置管理器、数据库连接池、日志对象;避免重复创建浪费资源、避免多处状态不一致
  • 面试常问:new 和 init 的区别 —— 一个造实例(先),一个初始化实例(后);只重写 init 拦不住”创建”这个动作

单例模式

11. 内置方法补充(getitem 系列、del)

🎬 对应视频:P409

让对象支持 obj[key] 要实现 getitem / setitem / delitem;对象被回收时触发 del;双下方法都是”特定语法自动触发”的钩子。

  • getitem(self, key):让 obj[key] 可用;setitem 支持 obj[key] = v;delitem 支持 del obj[key] —— 自定义容器类三件套
  • getitem 里拿到切片会是 slice 对象:isinstance(key, slice) 判断后按 key.start/stop 处理,就能支持 obj[1:3]
  • del 析构方法:对象内存被回收时自动调用,一般用来收尾(关文件、断连接);但触发时机不完全可控,别把关键逻辑依赖它
  • hash:返回对象哈希值,和 eq 配对自定义”怎么算相等”;放进 set/dict 做键的前提是可哈希
  • 记忆口诀:双下方法不用手动调 —— print 触发 __str__、加括号触发 __call__、方括号触发 __getitem__、with 触发 enter/exit

下标三件套

12. 菱形问题、MRO 与深度优先/广度优先

🎬 对应视频:P373、P375

B、C 都继承 A,D 又同时继承 B、C,同名方法该用谁的?这就是菱形问题**;py3 新式类用 C3 线性化(MRO) 解决,效果近似广度优先;py2 经典类深度优先会先撞上 A。**

  • 菱形结构:class D(B, C),B、C 都继承 A —— D 调用 who() 时,公共父类 A 出现在两条查找路径上,顺序必须定死
  • py3 一律新式类(继承 object),MRO 用 C3 线性化计算,类名.mro() 或 类名.mro 可查看完整查找链
  • 新式类菱形查找近似广度优先:D → B → C → A → object;B、C 的重写版本都优先于公共父类 A,写在继承列表前面的先找
  • py2 经典类按深度优先:D → B → A → C,A 先于 C 被找到,可能挡住 C 里的重写版本 —— 这正是 py3 改用 C3 的原因
  • super() 的真实含义不是”找父类”,而是”沿 MRO 找下一个类”;多继承里 super 链严格按 mro 顺序走

菱形继承的查找顺序

13. call 方法与元类控制类的产生

🎬 对应视频:P411P412、P414P415

对象加括号调用触发类里的 call;类加括号实例化触发元类 type 的 call——它先调类的 new 造对象、再调 init 初始化;在自定义元类里改写 call 就能拦截实例化(单例的终极写法)。

  • 实例可调用:类里定义 call(self, *args) 后,obj(3) 就像调函数一样执行它;callable(obj) 可检测对象是否可调用
  • 类的本质:type 是所有类的元类,类是 type 的对象;所以 类名() 触发 type.call,它内部依次调用该类的 new(cls) 和 init(self)
  • 定制元类:class Meta(type) 重写 call(cls, *args, **kwargs) 拦截”实例化”,在里面判断有没有已有实例就实现了单例;重写 new(mcls, name, bases, attrs) 则拦截”类的创建”,可校验/修改类属性
  • class Foo(metaclass=Meta) 指定元类;完整链路:类() → 元类 call → 类 new → 类 init,元类的 call 先于 Foo 的 new/init 执行
  • 记忆口诀:对象() 找类的 call;类() 找元类的 __call__。日常业务很少手写元类,读框架源码(如 ORM 的 Model)时才会遇到

元类拦截实例化
