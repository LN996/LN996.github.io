Python 入门与数据类型

发表于2026-11-01|Python基础
|浏览量:

我的学习笔记,边学边记,持续修订。

📖 计算机基础

1. 计算机五大组成

计算机五大组成:控制器、运算器、存储器、输入设备、输出设备;控制器 + 运算器 = CPU,程序的本质是”数据 + 指令”,全部用二进制表示。

  • 控制器:计算机的”指挥系统”,负责读取指令、分析指令、发出控制信号,协调各部件工作
  • 运算器:负责算术运算(加、减、乘、除)和逻辑运算(与、或、非、比较),是真正”算数”的部件
  • 存储器:保存数据和程序;分内存(电信号存储、速度快、断电丢失)与外存/硬盘(永久保存、速度慢)
  • 输入设备:把外界信息转成二进制给计算机,如键盘、鼠标、麦克风;输出设备:把二进制结果还原成人能看懂的形式,如显示器、音箱、打印机
  • 程序运行的本质:程序(指令 + 数据)先加载到存储器,CPU 不断”取指令 → 分析 → 执行”,结果交给输出设备呈现

2. 三大核心硬件与存储器(IO瓶颈)

三大核心硬件:CPU(运算+控制)、内存(临时)、硬盘(永久);速度 CPU 远快于内存、内存远快于磁盘,IO 才是程序性能的主要瓶颈。

  • CPU:中央处理器,内含运算器和控制器,只认识二进制指令,速度最快,负责真正干活
  • 内存(主存):电信号存储,速度比 CPU 慢但远快于硬盘,断电数据全部丢失,只能临时存放正在运行的程序和数据
  • 硬盘(外存):断电不丢,永久保存文件;机械硬盘靠磁头寻道慢、SSD 固态快得多,日常”拷文件慢”基本都卡在磁盘 IO 上
  • 速度金字塔:寄存器/高速缓存 > 内存 > 磁盘;CPU 与存储器差距太大,所以 CPU 内置寄存器、高速缓存先”垫一层”,减少等数据的时间
  • IO 瓶颈:程序运行要不断在磁盘 ↔ 内存之间搬运数据,读写远慢于计算;优化思路是少读盘、读一次多用多次(先把数据全部读进内存再处理)

3. 操作系统与计算机三层结构(含启动流程)

操作系统是介于硬件与应用软件之间的”管理者”:向下控制硬件、向上提供接口;计算机三层结构 = 应用程序 → 操作系统 → 硬件。

  • 操作系统的两大作用:① 把复杂丑陋的硬件操作封装成简单接口(打开文件、开进程、连网络) ② 管理调度众多应用程序对 CPU/内存/磁盘的竞争使用
  • 三层结构:最上层应用程序(QQ、Python 程序)→ 中间层操作系统(Windows/Linux)→ 最底层硬件(CPU、内存、硬盘);开发者只跟系统接口打交道,不必直接操作硬件
  • 操作系统启动流程:通电 → CPU 执行主板 BIOS 芯片里的程序(通电自检)→ 按 BIOS 里的启动顺序找到启动盘 → 读取磁盘开头的引导信息 → 把操作系统内核加载进内存 → 内核接管计算机,启动登录/桌面程序
  • 应用程序启动流程:双击图标 → 操作系统把程序文件从硬盘读入内存 → 分配 CPU 和内存资源 → CPU 开始执行其中的指令
  • 一句话理解:没有操作系统,每个软件都得自己写驱动、自己管内存;先有操作系统,程序员才能专注写应用

4. 编程语言分类(低级语言、高级语言、编译与解释)

低级语言(机器语言、汇编语言)直接面向硬件、难写难维护;高级语言要靠编译或解释翻译成机器指令,执行效率和开发效率不可兼得。

  • 机器语言:直接用 0/1 二进制写指令,CPU 可以直接执行,执行效率最高,但人几乎无法编写和阅读
  • 汇编语言:用英文助记符(如 mov、add)代替二进制,仍与硬件指令一一对应,执行快但开发效率极低,现在多见于底层开发
  • 高级语言(C、Java、Python……):用接近人类的语法写代码,开发效率高;但 CPU 只认机器码,执行前必须有人负责翻译
  • 编译型(C、C++、Go):编译器把全部源码一次性编译成目标平台的机器码 → 执行快、可以不发布源码,但换平台要重新编译,调试周期长
  • 解释型(Python、JavaScript):解释器逐行读取、逐行翻译执行 → 天然跨平台(各平台装对应解释器即可)、边写边调试,但执行速度慢
  • 选型思路:追求极致性能选编译型,追求开发速度和生态选解释型;Python”慢”的代价换来的是开发效率和跨平台

5. 平台与跨平台

*平台 = 操作系统 + CPU 架构的整体(如 Windows+x86、Linux+ARM);机器码不跨平台,Python 靠”各平台安装对应解释器”实现一份代码到处运行。*

  • 平台不只指操作系统:同样的 Windows,x86 与 ARM 的 CPU 指令集不同,同一份二进制不一定都能跑,所以平台 = **硬件(CPU)+ 软件(操作系统)**的整体
  • 机器语言/汇编语言直接面向特定 CPU 指令集,程序拿到别的平台基本跑不了,跨平台性最差
  • 编译型语言:源码跨平台、编译产物不跨平台 —— 换平台必须重新编译一遍
  • 解释型语言:Python 在 Windows/Linux/Mac 各装一个对应的解释器,同一份 .py 源码都能运行;翻译工作由解释器在运行时完成,这正是 Python 跨平台又稍慢的原因
  • 类似的还有 Java:源码编译成字节码,各平台装 JVM 来执行,”一次编写、到处运行”(了解)

6. CPU分类与指令集、内核态与用户态

CPU 只认识指令集里规定的机器指令,工作循环是取指令 → 分析 → 执行**;程序运行分内核态与用户态,应用程序想操作硬件必须通过系统调用交给操作系统内核代劳。**

  • 指令集:CPU 能识别的全部机器指令的集合,是硬件与软件之间的”接口”;常见 x86 架构属复杂指令集(CISC)、ARM 等属精简指令集(RISC),指令集不同,同一份二进制就不能通用
  • x86-64 中的 64:CPU 一次能处理的二进制位数叫”字长”,64 位 CPU 一次取 8 字节、寻址能力也更强(32 位系统最多认 4GB 内存,了解)
  • 寄存器:CPU 内置的”临时小仓库”,速度最快、容量最小;CPU 要先把数据从内存搬进寄存器才能运算,寄存器 + 高速缓存就是为弥补 CPU 与内存的速度差
  • CPU 工作流程:程序(指令 + 数据)加载进内存后,CPU 周而复始地取指令 → 分析指令 → 执行指令,结果写回内存或交给输出设备
  • 内核态与用户态:应用程序运行在用户态,没有权限直接操作硬件;要读写磁盘、发网络包必须发起系统调用陷入内核态,由操作系统代劳 —— 这就是三层结构中”操作系统管硬件”的底层机制,防止程序胡来搞崩整个系统
  • 多核与多线程:一个 CPU 封装多个核心可以真正并行干活;多线程是同一核心在多个任务之间快速切换(配合调度),了解概念即可

📖 Python入门与环境

1. Python语言特点与运行方式

Python 是解释型、动态类型、强类型语言,代码由解释器逐行执行,无需编译。

  • 解释型:写完直接运行,不需要像 C/C++ 那样先编译成二进制
  • 动态类型:变量不用声明类型,类型跟着值走
  • 强类型:1 + "1" 会报错,不同类型不能随便混算
  • 运行方式:交互式(python 直接进命令行)和脚本式(python xx.py)
  • 课程使用 Python 3.x(Python 2 已停止维护,print 在 py3 中是函数,必须加括号)

第一个Python程序

2. 变量与命名规范

变量就是给数据起名字,先赋值后使用,命名只允许字母、数字、下划线,且不能以数字开头。

  • 命名规则:字母/数字/下划线组成,不能以数字开头,不能用关键字(如 class、def)
  • 建议用小写+下划线的写法:user_name、max_count(见名知意)
  • Python 变量保存的是数据的引用(门牌号),b = a 是把 a 指向的地址也给 b
  • 查看类型用 type(x),查看内存地址用 id(x)
  • del 可以删除变量名

3. 注释与用户输入

注释用 #(单行)和三引号(多行),input() 接收的输入永远是字符串。

  • # 后面的内容解释器不执行;三对引号(未被赋值时)也可以当多行注释
  • input("提示语") 返回 str 类型,做数学运算前要 int() 转换
  • py3 的 print(a, b) 默认以空格分隔,end 参数可以改换行符

4. 常用运算符与优先级

重点区分 /(真除,得 float)、//(整除)、%(取余)、**(幂),逻辑运算优先级 not > and > or。

  • 7 / 2 = 3.5(py3 中 / 永远返回 float)、7 // 2 = 3、7 % 2 = 1、2 ** 3 = 8
  • 比较运算可以连写:1 < x < 10
  • 逻辑优先级:括号 > not > and > or;and/or 返回的是参与运算的值而不是布尔值
  • 成员运算 in / not in;身份运算 is 比较 id,== 比较值
  • 短路特性:and 遇到假就停,or 遇到真就停

5. Python解释器与程序运行的三个步骤

Python 代码由解释器执行:python xx.py 背后是启动解释器 → 把代码读入内存 → 逐行解释执行三个步骤,改完文件必须重新运行才生效。

  • 解释器就是运行 Python 代码的程序(python.exe):它负责把 Python 代码翻译成机器能执行的指令并执行,所以 Python 不需要像 C 那样单独编译
  • 三个步骤:① 启动 Python 解释器(相当于先打开一个软件) ② 解释器向操作系统发起系统调用,把 xx.py 的内容从硬盘读入内存 ③ 解释器解释并执行内存中的代码
  • 执行的是内存里的代码:文件保存后没有重新运行,跑的还是旧结果;这也是”改完代码报错消失/出现,必须再运行一次”的原因
  • 交互式(python 直接进命令行)适合临时验证一两行代码,关掉就没了;脚本式(python xx.py)把代码永久保存在文件里,是正式开发方式
  • 和文本编辑器的区别:记事本只会”读文件”不会”执行文件”;解释器读完之后还会执行,这是两者本质区别

运行Python程序的方式

6. 格式化输出(%、format 与 f-string)

把变量嵌进字符串有三种写法:% 占位符、str.format、f-string(py3.6+ 推荐);% 必须和类型一一对应,f-string 最简洁且大括号里能写表达式。

  • % 方式:”%s” 万能占位(什么都行),”%d” 只接整数,”%f” 小数(默认 6 位,%.2f 保留两位),”%%” 输出百分号本身;个数或类型不匹配就报错
  • format 方式:”{} {}”.format(a, b) 按顺序填;”{0} {0}”.format(x) 可以重复引用;”{:.2f}”.format(3.14159) 控制小数位数
  • f-string:f”名字是 {name}”,大括号里可以直接写表达式 f”{age + 1}”,变量名和值一目了然,py3.6+ 首选
  • 对比:% 老派但要记占位符类型;format/f-string 不挑数据类型;变量一多时 f-string 可读性最好
  • 共同点:三种方式都只是生成新字符串,不会改变原变量的值

三种格式化写法对比

7. 垃圾回收机制(GC)

Python 自动管理内存:以引用计数为主(计数为 0 立即回收),标记清除解决循环引用,分代回收降低扫描开销。

  • 引用计数:每个值身上都记录被多少个变量名引用;del 变量或变量重新指向别处会让计数减 1,减到 0 内存立即释放
  • 直接引用与间接引用:l1 = [1, 2] 中列表被 l1 直接引用,里面的元素 1 被 l1 间接引用;容器里的数据都是间接引用
  • 循环引用问题:a = []; b = []; a.append(b); b.append(a) 两个列表互相引用,计数永远不为 0,只靠引用计数回收不掉(内存泄露)
  • 标记清除:定期从”根”(所有变量名)出发沿引用链做标记,能到达的保留、不可达的整条链清除,从而解决循环引用
  • 分代回收:按存活时间把对象分成 0/1/2 三代,新对象在 0 代被频繁扫描,熬过的对象升级到老代降低扫描频率,用少量”漏回收”换取效率

8. 开发环境搭建:解释器安装、IDE 与虚拟环境

**写 Python 的三件套:**解释器(负责执行代码,必装)+ IDE(负责写代码,如 PyCharm、VSCode)+ 虚拟环境(给每个项目隔离第三方包)。

  • 解释器:从 python.org 下载对应平台的安装包;Windows 安装时建议勾选 Add Python to PATH,这样命令行任意目录都能直接敲 python
  • IDE(PyCharm/VSCode):集成”写代码、运行、调试、语法补全”的开发工具,比记事本高效得多;本质只是编辑器,真正执行代码的仍是背后配置的那个解释器
  • 虚拟环境解决什么问题:A 项目要 django 2.x、B 项目要 3.x,都往全局装必然打架;虚拟环境把解释器和包复制一份独立出来,每个项目用自己的环境,互不污染
  • py3.3+ 自带 venv 模块:python -m venv venv 创建;激活后提示符前出现 (venv),此时 pip install 只装进当前环境,deactivate 退出
  • IDE 里要给项目指定解释器路径指向对应虚拟环境,否则包装了 import 仍然报错 —— “环境不对”是新手最常见的报错来源之一

📖 六大基本数据类型

1. 数字与布尔值

int、float、bool 都属于数字类型,bool 是 int 的子类,True 就是 1,False 就是 0。

  • int:整型,长度没有限制;float:浮点型,注意精度问题 0.1 + 0.2 != 0.3
  • bool:只有 True / False,可以参与运算 True + 1 = 2
  • 0、0.0、””、[]、{}、None 都是假,其余为真
  • 常用转换:int("18")、float("3.14")、bool("")

2. 字符串 str(不可变)

字符串不可变**,所有“修改”操作都是产生新字符串;索引从 0 开始,切片 [start:end:step] 含头不含尾。**

  • 索引:s[0] 第一个,s[-1] 最后一个;越界访问单个索引会报 IndexError
  • 切片:s[1:4] 取下标 1、2、3;s[::-1] 反转;切片越界不报错
  • 常用方法:strip() 去两端空白、split() 切分、join() 拼接、replace() 替换、startswith/endswith、isdigit/isalpha
  • 格式化三种写法:"%s" % name、"{}".format(name)、f-string f"{name}"(py3.6+,课程推荐)
  • len() 统计的是字符个数而不是字节数

3. 列表 list 与元组 tuple

列表有序可变**,元组有序不可变;b = a 只是引用同一个列表,改 b 就是改 a。**

  • 列表常用方法:append(尾部加一个)、insert(指定位置)、extend(逐个合并)、pop(按索引删)、remove(按值删)、sort(排序)、reverse(反转)
  • 单元素元组必须带逗号:(1,),否则 (1) 只是数字 1
  • 元组不可变,但元组里的可变对象内容可以变:t = (1, [2, 3]),t[1].append(4) 合法
  • 浅拷贝 copy.copy() 只拷贝第一层,嵌套列表还是共享;深拷贝 copy.deepcopy() 全部递归拷贝
  • 遍历:for i in lst 或 for i, v in enumerate(lst)

4. 字典 dict(键值对)

字典是键值对结构,键必须是不可变类型**(str/int/tuple),py3.7+ 保证插入顺序。**

  • 增改:d[key] = value;删:del d[key]、d.pop(key)
  • 安全取值:d.get(key, 默认值) 键不存在不报错,d[key] 不存在会 KeyError
  • 遍历:for k, v in d.items();单独拿键 d.keys()、值 d.values()
  • 常用:setdefault、update 合并字典、in 判断键是否存在
  • 判断“在不在”字典时,in 查的是键

5. 集合 set(去重与关系运算)

集合无序、元素不重复**,天然用来去重;支持交、并、差集运算。**

  • 创建:{1, 2, 3},空集合必须 set(),因为 {} 是空字典
  • 去重:list(set(lst)) 缺点是无序
  • 关系运算:& 交集、| 并集、- 差集、^ 对称差集
  • 元素必须是不可变类型,集合本身可变(add / remove / discard)

6. 可变/不可变 与 数据类型转换

可变:list/dict/set;不可变:int/float/str/bool/tuple。这是判断“函数传参会不会影响原值”的基础。

  • 不可变类型修改值 = 产生新对象,id 会变;可变类型原地修改,id 不变
  • 常用转换:list("")、tuple(lst)、set(lst)、str(123)、int("18")
  • eval 可以把字符串当表达式执行(有安全问题,慎用)
  • is 判断是否同一个对象(id 相同),== 判断值是否相等

7. bytes 类型与编码解码(encode / decode)

str 是给人看的,bytes 是给机器/网络用的;s.encode() 编码、b.decode() 解码,用什么编码存就用什么编码取才不会乱码。

  • 定义 bytes:字面量 b”hello”、b”\xe4\xb8\xad”;取单个元素得到整数:b”abc”[0] → 97,而 “abc”[0] → “a”
  • 编码 str → bytes:s.encode(“utf-8”);解码 bytes → str:b.decode(“utf-8”);编码和解码必须用同一张表,utf-8 存的用 gbk 解必然乱码
  • 字节数:英文、数字在任何编码下都占 1 字节;中文在 utf-8 占 3 字节、gbk 占 2 字节 —— 这就是同一个文件 utf-8 比 gbk 大的原因
  • py3 内存中的字符串统一是 Unicode,存盘、走网络前必须 encode;以 b 模式读写文件、socket 收发的数据都是 bytes
  • utf-8 与 gbk 之间不能直接转,要以 Unicode 为中转:先 decode 成 str,再用另一种编码 encode

8. 队列与堆栈(用列表模拟)

队列:先进先出 FIFO(尾部进、头部出);堆栈:后进先出 LIFO(一端进出);都可以用列表的 append + pop 模拟。

  • 队列(queue)像排队买饭:先来的先走;存:lst.append(x)(尾部进),取:lst.pop(0)(头部出)
  • 堆栈(stack)像叠盘子:最后放的先被拿走;存:lst.append(x),取:lst.pop()(尾部出)
  • pop(0) 每次要把后面所有元素整体前移,数据量大时效率低;实际项目用 collections.deque(append 进 + popleft 出)实现队列
  • 记忆:同一个列表,”取哪头”决定它是队列还是栈 —— pop(0) 是队列,pop() 是堆栈

用列表模拟队列与堆栈

9. 数字类型细节(进制表示与浮点精度)

py3 的 int 没有长度上限,float 有精度误差(0.1 + 0.2 != 0.3);二/八/十六进制用 0b / 0o / 0x 表示,bin/oct/hex/int(x, base) 负责互转。

  • int 不限长度:多长的整数都能直接算(py2 还区分 long,py3 统一为 int)
  • float 近似存储:print(0.1 + 0.2) → 0.30000000000000004;判断相等不要用 ==,用 abs(a - b) < 0.000001 这类写法或 decimal 模块
  • 进制字面量:0b1010 二进制、0o17 八进制、0xff 十六进制,print 出来都是十进制(10、15、255)
  • 互转函数:bin(10) → “0b1010”、oct(10) → “0o12”、hex(255) → “0xff”;反向用 int(“1010”, 2)、int(“ff”, 16)
  • divmod(7, 2) 一次拿到商和余数 (3, 1),常用于分页计算;round(x, n) 四舍五入(注意是银行家舍入,了解)

10. 字符串内置方法清单(优先掌握/需要掌握/了解)

字符串方法按优先级背:优先掌握 strip、lower/upper、startswith/endswith、split、join、replace、format、isdigit;需要掌握 find/index/count、center 等;所有方法都不改原字符串**,只返回新值。**

  • 优先掌握① 去空白与大小写:strip() 去两端空白(可传参去指定字符)、lstrip/rstrip 只去左边/右边;lower()/upper() 全小/大写,capitalize() 首字符大写其余小写,title() 每个单词首字母大写
  • 优先掌握② 判断类:startswith()/endswith() 判定开头结尾(常用于文件后缀);isdigit() 是否纯数字(校验用户输入);isalpha() 是否纯字母
  • 优先掌握③ 切分与拼接:split(分隔符, 次数) 按分隔符切成列表(不传参默认按任意空白切),rsplit 从右切;join 把元素全为字符串的可迭代对象用指定字符连接 —— split 与 join 是天生一对
  • 优先掌握④ 替换与格式化:replace(旧, 新, 次数) 全部/限定次数替换;format(“{}{}”) 填占位符,支持 {0} 位置引用和 {name} 关键字引用
  • 需要掌握:find 找子串返回索引、找不到返回 -1;index 功能同但找不到直接报错;count 统计子串出现次数;center(宽度, 填充符)/ljust/rjust 居中、左对齐、右对齐填充
  • 了解:expandtabs 把 \t 转空格、zfill(n) 左侧补零、isalnum/isspace 等其余 is 系列;方法不用死记,会用 dir(str) 和 help() 现查

11. 深浅拷贝详解(copy.copy 与 copy.deepcopy)

b = a 只是取别名不是拷贝;copy.copy 浅拷贝只复制**第一层(嵌套的可变对象仍然共享),copy.deepcopy 深拷贝递归复制所有层,和原对象完全独立。**

  • 赋值 b = a:两个名字指向同一个列表,通过 b 的任何修改 a 都看得见,根本不算拷贝
  • 浅拷贝 copy.copy(a):新建一个外层容器,把第一层元素的引用逐个放进去 —— 第一层从此独立,第二层及更深仍然共享同一个对象
  • 深拷贝 copy.deepcopy(a):递归把每一层可变对象都新建一份,改动任何一层互不影响;代价是更慢、更占内存
  • 隐藏考点:切片 lst[:]、list(lst)、字典 d.copy()、集合 set(lst) 得到的都是浅拷贝
  • 怎么选:看嵌套结构里有没有可变对象(列表/字典/集合)—— 没有则浅拷贝够用;有且需要彻底隔离就用 deepcopy
